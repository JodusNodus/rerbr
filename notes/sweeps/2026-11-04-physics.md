# Physics sweep, 2026-11-04

`scripts/sweep-physics.py`: the autopilot (`rbr-standalone --autopilot /dev/null --boot`, headless, the launcher's
real arguments from `rerbr --command`) drives each stage × car to the finish; the script reads the exit code, the
stderr, the progress lines (every 500 steps, now with the position) and `--result-out`. Outputs:
`$RBR_RUNS/sweep-physics-2026-11-04/` (`summary.json`, `summary.txt`, `runs/<name>/`; not in git).

## What ran

324 runs, 11 at a time, about 40 min elapsed (7.1 h of run time under a loaded machine, 2 to 7 simulated seconds per
second, the slowest 350 s for 1031 s of drive). Build of this branch (main plus the script).

## Findings

**No physics problem.** Across all 324 runs there is no `declined`, `unbound`, pure-step stop, panic, NaN or
infinity in stderr or the progress positions, and no run slower than expected. Realistic damage (parts detaching)
ran 108 times without a panic. So no code or exe-data fix was needed; nothing was changed in `rbr-physics`,
`rbr-hybrid` or `exe_data.rs`, and the parity check was not run (nothing to check).

## Changes in this branch

- `scripts/sweep-physics.py`: the sweep (`--out`, `--only`, `--jobs`, `--cars`, `--list`, `--dry`, `--sample`,
  `--resummarize`).
- `rbr-launcher --list` also prints `Startable: <map>` and `Startable car: <car>` lines (the script reads the map
  numbers of BTB stages, which have no fixed id, from it).
- The autopilot's progress line shows the height above the driveline and the position.

Checks: `cargo clippy -p rbr-launcher -p rbr-standalone --all-targets -- -D warnings` and `cargo fmt --check` clean;
`cargo test --release -p rbr-launcher -p rbr-standalone` pass (the launcher's pass with `RBR_NGP_DLL` set; two of its
tests fail without it, unrelated to this change).
